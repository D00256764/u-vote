    - Checks out repo with GITHUB_TOKEN for write access

Author: hafsa <d00256764@student.dkit.ie>

Message: feat(CV-17): enable CI pipeline - lint fixes, BASE_URL portability, ruff config
This commit makes the full GitHub Actions CI pipeline pass and prepares the
codebase for multi-environment deployment (Docker Compose + Kubernetes).

Triggers: every push to any branch; PRs targeting main or mvp_tests.

Job 1 — Lint (ruff)
  Runs ruff check across all Python source files. Enforces code style,
  catches unused imports, bare f-strings, and ambiguous variable names
  before any tests run. Fast-fails the pipeline immediately if style
  violations are present.

Job 2 — Unit Tests (matrix: 6 services in parallel)
  Runs pytest for each service independently:
    auth-service, voting-service, election-service,
    results-service, admin-service, frontend-service
  Each job installs that service's requirements.txt plus requirements-dev.txt,
  then runs all tests under {service}/tests/ with verbose output and JUnit XML
  results uploaded as artifacts for reporting.
  Uses fail-fast: false so all services are tested even if one fails.

Job 3 — Unit Tests (shared modules)
  Tests the shared/ library (logging_config, security, schemas) which is
  imported by all 6 services. Runs tests/test_logging_config.py and
  tests/test_shared.py. Depends on lint passing.

Job 4 — Integration Tests (Docker Compose + NGINX)
  Spins up the full stack with docker compose up -d, waits for:
    - PostgreSQL to report healthy (up to 120s)
    - NGINX gateway on port 80 to accept connections (up to 90s)
  Then runs tests/test_integration_compose.py — real HTTP flows through
  the NGINX gateway covering:
    - Public pages (home, login, register) return 200
    - Auth-gated routes (/dashboard, /results, /voters) redirect to /login
    - Voting-service reachable, invalid tokens return error page
    - Full register → login → dashboard end-to-end flow
    - NGINX routing correctness (each path prefix hits the right service)
  Prints all service logs on failure for debugging, then tears down the
  stack with docker compose down -v regardless of outcome.

Job 5 — Docker Build
  Runs docker compose build to verify all 6 Dockerfiles still build
  cleanly after every change. Depends on unit tests passing (jobs 2+3).

Job 6 — Trivy CVE Scan (matrix: 6 images)
  Builds each Docker image individually then scans with Trivy for CVEs
  at CRITICAL and HIGH severity levels. Findings are written as SARIF
  and uploaded to the GitHub Security tab via codeql-action/upload-sarif,
  making vulnerabilities visible as security alerts on the repository.
  Uses continue-on-error: true so CVEs are surfaced without blocking
  merges while they are being remediated.

Job 7 — Trivy Filesystem Scan
  Scans the repository source code for hardcoded secrets, exposed
  credentials, and infrastructure misconfigurations (Dockerfiles,
  docker-compose.yml, K8s manifests). Output uploaded to GitHub Security
  tab as a separate SARIF category.

CHANGES IN THIS COMMIT

ruff.toml (new):
  Suppress E402 project-wide. Every service inserts sys.path before
  importing shared/ modules — this is intentional and consistent.
  Excludes plat_scripts/ and database/ from linting.

Lint fixes (ruff auto-fix + manual):
  F401 — removed unused imports across admin-service, voting-service,

  F541 — removed f prefix from strings with no placeholders (test_api.py,
         test_db.py, test_logging_config.py)
  F841 — removed unused exc variable in tests/test_api.py
  E741 — renamed ambiguous l loop variable to ln in boot_platform.py,

BASE_URL env var (portability for Kubernetes):
  Replaces hardcoded http://localhost in _require_login redirects and all

  works identically in Docker Compose (localhost) and Kubernetes (any
  ingress hostname e.g. http://uvote.local).
  templates.env.globals["base_url"] = BASE_URL injects it into all Jinja2

**docker-compose.yml**
- Adds nginx service: image nginx:alpine, port 80:80, mounts nginx/nginx.conf read-only
- Removes host port mappings for auth-service (5001), admin-service (5002),
  voting-service (5003), results-service (5004), election-service (5005) —
  these are now reachable only on the internal voting-network Docker bridge
- Keeps frontend-service port 8082 as a direct dev fallback
- Updates FRONTEND_URL (admin-service) from http://localhost:5003 to http://localhost
  so voting token links in emails route through NGINX on port 80
- Updates ELECTION_DASHBOARD_URL (frontend-service) from http://localhost:5005/dashboard
  to http://localhost/dashboard
- Updates ELECTION_SERVICE_URL (results-service) from http://localhost:5005
  to http://localhost so browser redirects from results-service go through NGINX

**Template and app.py hardcoded URL updates**
Replaced all localhost:PORT references with localhost (port 80 via NGINX):
- election-service/app.py: _require_login redirect → http://localhost/login
- results-service/app.py: _require_login redirect → http://localhost/login
- admin-service/app.py: _require_login redirect → http://localhost/login
